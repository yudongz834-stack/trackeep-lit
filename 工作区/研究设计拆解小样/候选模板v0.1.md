# 临床论文设计拆解候选模板 v0.1

用途：从真实全文保留研究为什么这样设计、怎样形成证据，以及迁移时需要什么条件。每张卡按以下三层填写；候选模板尚未成为正式规则或技能。

## 设计类型

分轴填写：干预或观察；随机与否及具体亚型；资料采集时间方向；单中心或多中心；数据来源。允许“随机试验＋前瞻性＋多中心”同时成立。回顾性电子病历队列中，结局仍可按暴露之后的时间顺序随访。

## 可复用模式

| 字段 | 要填写的内容 |
|---|---|
| 模式名称和作用 | 一句话说明它支持什么比较或判断，不以某个统计方法命名 |
| 比较结构 | 干预、对照及共同资格；是否动态改变身份 |
| 时间结构 | 时间零点、暴露确定、结局起算、风险窗及随访终止分别填写 |
| 证据步骤 | 从选人到分组、观测、分析、偏倚检验，保留先后依赖 |
| 偏倚与验证 | 每个措施对应哪种偏倚；验证结果及仍未排除的解释 |
| 迁移条件 | 哪些资源和假设必须满足；哪些人群、终点或场景不能直接沿用 |
| 相似性判定 | 比较结构、时间零点、偏倚控制、验证路径四项逐项比较；同名方法不能单独决定合并 |

这里填写的是【模式提炼】，不能冒充作者原话。归入共同模式族时仍保留各分支和全部论文实例。任何关键项未知，先标“待核”，不自动合并。

## 论文实例

| 字段 | 要填写的内容 |
|---|---|
| 身份和关系 | 作者、年份、期刊、DOI、研究或注册编号；主报告、随访、亚组或方案关系；资料和人群重叠状态 |
| 问题与人群 | 具体问题、资格、排除、场景；研究对象与最终分析对象区别 |
| 设计坐标 | 按上面的各轴填写，附原文措辞或定位；分类解释标【推断】 |
| 分组与时间 | 干预或暴露、对照；分配或匹配；时间零点、结局起算、风险窗、换组和删失 |
| 终点 | 主要疗效、安全性或多个主要结局分别记定义和时间点；不要自行选一个代表全部 |
| 证据步骤和偏倚 | 实际采取的设计措施、分析和敏感性检查，以及作者承认的限制 |
| 统计设计 | 样本量依据；随机、观察和分析单位；分析人群；效应量、参照方向、单位、95%CI；主分析、缺失、删失和多重性 |
| 资源与瓶颈 | 作者明确报告的资源标【事实】；迁移所需资源及瓶颈判断标【推断】；不编预算、工期或难度分 |
| 结果与限度 | 只留支撑设计理解的关键结果；同一结果不能跨人群、时间或终点外推 |
| 来源与核对 | 官方全文链接及版本、节名、表图号或PDF页码；补充材料与方案是否实际读到 |

每条有实质内容的陈述标【事实】【推断】或【模式提炼】，并紧邻定位。空缺区分“正文未报告”“附件本次未核”“来源不可得”，不能用一个空白代替，也不能据未读附件断言整篇未报告。

统计设计随主卡保存；建模代码、诊断和统计执行细节留给未来单独模块，本轮不开发。CONSORT/STROBE只用于检查报告字段，不能据清单齐全宣称设计正确或打质量总分。

## 分层保存和增量修订

| 层 | 唯一主记录 | 版本和依赖 |
|---|---|---|
| 来源材料和证据定位 | 官方原件及来源回执，区分正文、附件、方案 | URL、取得日期、文件哈希和版本；定位随该原件版本保存 |
| 事实提取 | 每篇论文卡；不把事实在多个主题下各复制一份 | 稳定论文ID、抽取规范版本、修订号；字段状态及所依赖的来源和定位见字段依赖表 |
| 模式归纳 | 候选模式主记录，通过ID或链接关联实例 | 模式版本、依赖字段；支持和反例并存，变更不能删掉实例差异 |
| 质量评价 | 独立审阅记录 | 席位、审阅范围、所审来源与卡片版本、发现及关闭状态；评价变化不反写作者事实 |

本次已用Markdown、原件回执和[字段依赖表](字段依赖.json)演示这四层，不部署数据库。事实值在卡片，依赖表只记录状态和位置，防止出现第二份事实正文。

修订按影响范围进行：新增字段只补相关实例的该字段，其他实例可先保留“未提取”；模式名称或标签变更只更新归纳和索引；抽取定义变化只重提受影响字段及下游；来源更新、实质误抽或定位失效才针对性重读原件、重审受影响项。遇到关系无法追溯、版本不兼容或广泛系统性误抽，需要扩大重审范围，不能保证零重跑。旧版保留，不静默覆盖已审依据。

字段状态包括“已报告并定位”“正文未报告”“本次未核”“审阅者推断”“存在争议”“来源失效”。“正文未报告”不能扩展成“研究没有做”。依赖缺失或来源变化时，下游模式转为待复核，不能继续沿用旧的通过标记。

## 两席审阅和可调用状态

事实席与提取者分开，检查原文忠实性、数字、定位和事实/推断分界；方法席与提取者分开，检查比较、时间零点、偏倚、统计及结论边界，分别列出可借鉴、条件性借鉴、不可直接复用的部分。两席均为AI，本次实审记录见[审阅记录](审阅记录.md)。两席一致也不保证科学正确；重大争议保留“待专业复核”。

事实核验与方法学可借鉴性是两条状态轴，不能用一个“通过”覆盖二者。候选生命周期可用“未审／有争议／已审可用／失效”，但“已审可用”仅表示注明条件的单元可检索借鉴，并非原论文整体可信背书。未来供Agent调用必须同时满足：来源可核、事实审阅覆盖所用字段、方法适用条件明确、无阻断争议、依赖版本有效。当前三篇均是候选小样，未发布为Agent默认规范。

## 未来Obsidian管理契约

Obsidian作为人可读入口，采用Markdown、少量固定属性和证据链接。论文以规范化DOI或其他稳定ID识别，标题变化不改变身份；单元模式和审阅各有稳定ID。设计类型、疾病和主题用属性或链接关联，正文不复制到多个目录。主记录之间用链接，目录和索引应能从主记录重建。

最小属性为id、kind、revision、extraction_spec、status、source_manifest、review_record；来源版本与字段依赖沿上述记录取，不把长日志塞入每张笔记。Zotero将来保留原文的唯一来源链接；是否把PDF搬入笔记库尚未决定，本次本机原件仅用于小样核对，没有写Zotero。正式落入Obsidian前先查既有Trackeep笔记库布局与管理规则，当前不建库、不迁移、不装插件。

## 覆盖与版本门槛

本轮同主题三篇只验证起步字段。后续小批代表性样本可覆盖集群/交叉或非劣RCT、前瞻性与回顾性队列、病例对照、诊断准确性及重复报告；重点补不同的时间零点、终点和数据缺失结构，不追求堆数量。正式版本发布前应证明字段能表达这些差异，两席核完承重字段，争议与迁移限制可见，旧版到新版的受影响字段可追溯，并由PI确定发布范围。尚不能据此定稿所有临床设计规范。
