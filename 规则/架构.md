# Trackeep Literature 架构定位

接闸：CI `quality-gates / tests` 在测试前执行 `tools/check_map.py --check`；本地收口同样先查。只有本地证据不代表 GitHub CI 已运行。

## 1. 系统是什么

现役项目包含桌面文献进料端；本轮新增独立的 PubMed 只读预览，不加载 Zotero/AI 凭证，不连接写入引擎。检索规则入口见 [AGENTS.md](../AGENTS.md)。旧桌面检索仍有历史路径与过滤口径，不能混同新预览。

## 2. 故障去哪查

预览检索报错先读 `日志/pubmed-preview/` 对应回执，再查 `lit/pubmed.py`：`prepare` 管输入、`esearch` 管解释/警告/返回结构、`collect` 管分片数量、`metadata` 管题录身份；`preview` 做指定期刊 NLM ID 对账。错刊先对 `.project/pubmed-journals.json`，不要放松身份断言。缺文件/格式错误由 `main` 反馈；外部网页的文字不是本地代码指令。

同篇跨月重复或卷期更新看 `compare_previous`：只读 `--previous` 指定的历史报告，按 PMID 分已见/新增，保留字段差异；DOI 冲突待核，标题不参与自动合并。没有历史报告不报全局新增；不负责 Zotero 库更新。

旧 GUI 起窗/回执问题看 `ui/main_window.py`、`ui/pages/harvest_page.py`，子进程接线看 `lit/engine.py`，路径看 `lit/config.py`；这些旧入口不在本阶段新规则生效范围。规则与代码不一致看 `tests/pubmed_test.py` 和独立复核，不以聊天自报为验收。

## 3. 新功能加在哪

新增合法期刊先核官方 Catalog，再改 `.project/pubmed-journals.json`；新增日期口径改 `prepare` 允许字段并加反例测试，再改检索规范。主题概念内容在计划文件，不在代码里硬编码研究主题。跨阶段筛选、Zotero 字段/写入与全文仍待单独阶段，不接进这个只读模块。

## 4. 各块怎样协调

Agent 读规则 → 显式 JSON 计划 → `python -m lit.pubmed` → NCBI ESearch / EFetch → 新建本地 JSON 回执。结果集合、缺摘要与撤稿标记都保留；退出码分清阻断/待核/取齐。入口不启动外部引擎、不调用 GUI、不导入 Zotero 模块。规则正文属于 `规则/`；期刊机器身份属于 `.project/`；运行记录属于忽略入 Git 的 `日志/`。既有 Zotero 数据、附件和凭证位置不变。

下面的源码体量和依赖表由源码静态生成；不把实际后台服务或未合入的隔离分支算作现役能力。CLI 参数业务含义由规范维护；生成器不重复维护第二张接口表，所以无两源表需要对账。
