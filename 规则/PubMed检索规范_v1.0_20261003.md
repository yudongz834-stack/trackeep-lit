# Trackeep Literature：PubMed 检索规范

版本 v1.0 · 2026-10-03 · 读者：首次接手项目的 Agent 与 PI。

这是本管道检索规则的唯一正文。适用期刊采集和主题找文献；仅规定检索、核对与交接，不授权 Zotero 写入。**PI 已定顺序：自然语言范围 → 核验 PubMed 检索及题录 → Zotero 题录导入 → Agent 入库后相关性与重复复核 → 可逆清理 → 仅为保留项获取全文**。明确、无歧义的范围先写进检索式，不确定判断留到入库后；数量齐不等于相关性正确，更不等于出版社全刊收齐。

标记含义：**官方事实**有来源；**已实现**指代码强制检查；**实测**须附带日期与运行证据；**建议/待定**不能冒充已经定案的规则。实测覆盖见[阶段日志](../阶段日志.md)，运行原始回执在 `日志/pubmed-preview/`，不是本规范中的固定数字。

## 1. 每次先形成检索计划

Agent 把用户意图写为 JSON 计划，交给 `lit/pubmed.py`。自然语言转检索式目前由 Agent 完成，没有隐藏的模型改写服务。

必须说明：①期刊采集或主题检索；②期刊身份或概念范围；③起止日期及生效日期字段（按刊省略字段时采用下文已定默认，主题仍须显式指定），主题确实不限时则显式 `all_time: true`；④检索前过滤条件和理由；⑤筛选位置 `undecided` / `before-import` / `after-import` / `split`；⑥已知应命中的 PMID（如果有）。患者身份信息不得进入检索式。

“今年”“最近”“某刊某年”应先换成具体日期并向用户回显。期刊采集没有日期就停止，不猜当年；主题未给时间可提出不限时方案，但不得暗填最近一年。省略筛选位置时采用 `after-import`；显式 `undecided` 仍表示该计划待定，只做预览，不能自动批准导入。缺摘要或模型未作判断保留待核，不自动排除。

**已实现的入口**（项目根执行，复用现有 Python，不安装依赖）：

```powershell
& .\venv\Scripts\python.exe -m lit.pubmed --plan .\规则\示例\nature-month.json
```

退出码：`0`＝检索集合、题录及适用身份核对通过；`2`＝已取回但有警告或召回验证待核；`1`＝阻断。即使为 0，`relevance_validated` 仍为 false，不表示主题相关性已通过人工判断。每次运行落独立 JSON，包含输入、服务端解释、错误/警告、PMID、题录、分片与计数；失败也留证。

旧 GUI 和旧 PowerShell 按刊检索尚未接入本规范的完整校验，**不能把旧界面回执当本阶段合格预览**。本阶段 Agent 使用以上入口；题录导入正通过原 PowerShell 引擎补齐精确身份护栏；少量实测走 `lit.metadata_batch`，仍须独立复核。全文和插件封装不在本阶段。

## 2. 期刊采集：先核刊，再核时间

**已定产品决定（PI 2026-10-03 授权代定日期口径）**：电子上线即可进入采集候选，不等正式编期，目标是尽早收集。机器按刊默认用 `dp` 覆盖日期范围，不把仅 `epdat` 作为排他过滤，以免因缺电子日期漏收。目标与当前策略不同：`dp` 是取候选的时间口径，不是“首次上线”断言，也不代表已实现持续增量追踪。

**已实现**：按刊计划有起止日期但省略 `date.field` 时，入口补 `dp`，原输入保留，`effective_plan` 与 `date_policy` 记录生效字段及默认/显式来源；缺日期范围仍阻断。用户明确要求仅电子或仅印刷日期时指定 `epdat` / `ppdat` 覆盖默认，回执注明该字段缺失或尚未编期造成的范围局限。显式空值、拼错字段不当成默认。示例 `nature-month.json` 演示省略字段采用默认；筛选位置采用已定的 `after-import`。

电子上线与卷期日期分别保留原始字段及来源；`date_sources.electronic/issue` 明示 `reported` 或 `missing`，缺失不从另一日期推造，不补不存在的月/日或“首次上线日期”。迟入库补录、回看窗口及 Zotero 存量更新仍属后续阶段。

**官方事实**：期刊字段 `[TA]`（Journal）可以用完整刊名或标准缩写；只有 ISSN 的查询可能漏掉不含 ISSN 的旧记录。查询用已核实的标准缩写，返回题录用 `MedlineJournalInfo/NlmUniqueID` 校验，二者不同职责。[NLM 检索帮助](https://pubmed.ncbi.nlm.nih.gov/help/#searching-by-journal)

七刊 Nature、Science、Cell、NEJM、Lancet、JAMA、BMJ 的身份正本是 [pubmed-journals.json](../.project/pubmed-journals.json)，每条附 NLM Catalog 来源；不要在别处另抄一套缩写/ID。**已实现**：只接受表内明确别名，逐条核 NLM ID；缺失或不符即阻断。其余刊需先核官方记录再扩表。

历史边界：主刊不自动包含系列刊、分刊、前身或摘要版。BMJ 主刊与 Academic edition 是不同记录；Lancet 的 Catalog 网页编号也不是 NLM ID。回溯更名前年份须另核前身集合，不因为本表七刊可用就声称覆盖所有历史。Nature 官方记录注明 PubMed 选择性收录，所以“PubMed 取齐”不能称“全刊收齐”。[Nature Catalog](https://www.ncbi.nlm.nih.gov/nlmcatalog/410462)

| 日期口径 | 含义与使用边界 |
|---|---|
| `dp` | 发表日期，可能命中电子或印刷日期；电子日期晚于印刷日期时有官方例外。不是“首次上线”。 |
| `epdat` / `ppdat` | 分别限定电子／印刷出版日期；不是每篇都具备，不得认为两者并集以外没有记录。 |
| `crdt` | PubMed 记录创建日期；持续追踪新入库记录的候选口径。 |
| `edat` | PubMed 处理用 Entry Date；不要把它解释为发表日期或绝对不变的首次入库日。 |

日期范围含首尾，使用明确的 `YYYY/MM/DD:YYYY/MM/DD[field]`。年或月转成该年/该月首尾日，闰年按日历计算。只有年、季节、日期区间的题录由 PubMed 按其规则映射，不能自行补成真实发表日。索引会补录/更新，日后重查计数可变；持续增量的回看窗口与锚点更新尚未实现。[官方日期说明](https://pubmed.ncbi.nlm.nih.gov/help/#publication-date-dp)

### Online first 与正式编期：日期变了，不等于新增一篇

**官方事实**：提前在线发表的正式期刊论文编入卷期时，通常更新原 PubMed 题录并去掉 ahead-of-print 提示；电子日期和卷期日期可以相隔数月。它不同于独立预印本，不能因为“还没编期”就当预印本。[PubMed 出版日期说明](https://pubmed.ncbi.nlm.nih.gov/help/#publication-date-dp)

**执行规则**：把 PMID 作为 PubMed 记录身份，把电子/印刷日期作为可更新元数据。跨月遇到同 PMID，记录已见及元数据差异，不按月份再算一篇新论文；保留前后报告及两个日期来源，不覆盖历史。不同 PMID 即使标题相同也保留为不同对象；同 DOI 对应不同 PMID、同 PMID 的 DOI 不一致均须核 DOI 与关联关系，不自动合并。预印本、勘误、撤稿通知、重发版本分别保留其真实类型和关系。

**已实现**：预览可重复传 `--previous <历史预览JSON>`，只读比较明确提供的报告。源命中数不变，另报 `seen_count`、`new_count`、`metadata_changes`、`identity_conflicts`；同 PMID 卷期/状态改变进入更新清单。历史不可读、不完整或结构错则阻断；未提供历史标 `not_evaluated`，不能声称“全库新增”。多份历史按报告时间排序；已知 DOI 冲突保留待核。这里只比较本地检索快照，不查 Zotero 是否已存在，不自动更新 Zotero。

**实测边界**：2026-10-03 对 PMID 42420446 分别检索 7 月和 9 月 `[dp]`，两次均命中同 PMID；题录电子日期为 7 月 8 日、卷期日期为 9 月。这证明当前记录可以跨月重现，**不是保存了 7 月时的历史快照**。真实编期前后元数据变更尚无历史抓取证据；用合成的 ahead-of-print→有卷期反例测试验证更新分流，不冒充长期线上实测。对应回执和测试位置见阶段日志。

期刊模式必须显式选：

- `broad`：只有刊与日期，作为查全基线候选，不暗加有摘要、研究类型或生物医学过滤。
- `query-filtered`：额外 `filter_query` 与 `filter_reason` 必填。先记录宽基线，再记录过滤后集合与差集理由；入口目前只执行当前一份计划，两份对账由 Agent 完成，不能谎称已自动完成。

`Journal Article[pt]` 不是“仅原创研究”的可靠开关，`Review[pt]` 也不覆盖所有尚未标引的综述。缺摘要不能证明无价值；不得将 `hasabstract` 当无损清理。人类、语言、年龄、MeSH、文章类型等过滤都可能牺牲召回，只有用户范围要求或明确记录的候选策略才加入。[官方过滤说明](https://pubmed.ncbi.nlm.nih.gov/help/#filters)

## 3. 主题检索：概念组而非整句翻译

1. 把问题拆成最少的必要概念，例如疾病/人群、干预、研究对象。不要机械地把 PICO 每项都 AND 进去；结局、比较组写法多时先留到筛选，以免漏检。
2. 每组列出规范 MeSH 词及自然语言同义词、英美拼写、旧名/缩写。MeSH 词先在官方 [MeSH Browser](https://meshb.nlm.nih.gov/) 核实；未核实词标为候选，不能伪装成有效主题词。
3. 组内 OR，组间 AND，每组加括号。自由词逐个标 `[tiab]`，主题词标 `[Mesh]`；仅标题用 `[ti]` 会更窄，须有理由。MeSH 默认扩展下位词，`[mh:noexp]` 仅在明确要限制时使用。
4. NOT 可能删掉同时讨论两类对象的相关文献，原则上先用正向条件；确需 NOT 时记录理由并抽查排除集合。不能凭“看起来不相关”把标题词变成全局排除词。
5. 字段、引号、截词会改变自动映射。`*` 前至少四个字符，通配符不替你补 MeSH；无效短语可能被拆词或忽略引号。检查服务端 QueryTranslation，不能只看自己写的原式。[语法与映射](https://pubmed.ncbi.nlm.nih.gov/help/#searching-for-a-phrase)
6. 用至少一篇明确应命中的已知 PMID 验证召回；缺失时分拆概念组定位哪项误排，并保存修前/修后计划。没有已知文章时仍可探索，但标为未完成召回验证。命中种子不是总体召回率证据；再抽看相关与不相关样本，决定是前端收紧还是后端筛选。

可运行的[主题示例](示例/stem-cell-topic.json)将“Nature 2026 年 9 月造血干细胞移植”拆成 MeSH 与英美拼写自由词，并带已知 PMID；这是检索演示，不是生物医学总筛选规则。每次概念调整要有漏检/误检实例或用户范围变化，不做无目标的反复改词。

## 4. 服务端解释、数量与身份：机械检查的边界

**官方事实**：ESearch 默认只返回 20 条；PubMed ESearch 只能取前 10,000 条，不能靠不断增加 retstart 获取任意大集合。可按日期分段或采用官方 EDirect。[E-utilities 参数](https://www.ncbi.nlm.nih.gov/sites/books/NBK25499/#chapter4.ESearch)

**已实现**：明确请求 9,999 条；超过则递归拆日期，逐叶检查 `Count＝返回数＝唯一 PMID 数`。跨分片可能因多发表日期重复，取并集，并与父查询 Count 核对；不简单相加。单日仍超限、无日期的超大主题查询、父子数量不合均阻断。当前不装 EDirect，不声称能取任意大集合。

EFetch 每批 150，检查该批返回 PMID 集合与请求完全相同；重复、漏篇、错篇或当前解析器不支持的记录类型都阻断。期刊采集额外核 NLM ID。摘要缺失单独计数，保留原文题录；撤稿状态单独标记。

**已实现**：原始 ESearch 回执、QueryTranslation、warninglist/errorlist 都保存；有 errorlist 的有效内容即阻断，有警告即退出 2 待核，绝不静默吞掉。已取齐与警告待核可以同时成立。元数据保留来源 URL、日期字段、关联关系及每批原始字节哈希；哈希不是原文备份，当前不保存全部 EFetch XML。

**Agent 必做但未机器判定**：判断解释是否符合语义、审查主题式概念映射及抽样相关性。网页 Advanced → History → Search Details 与 API 比对时，用同一查询、同一时点范围，并检查网页是否残留筛选；不改用户全局设置。静态读取不通再按 webaccess 用自建后台 tab，结束关闭。本次 Nature 样例已比对一致，不外推为所有复杂式永远一致。

## 5. 撤稿与筛选交接

**官方事实**：撤稿原文与通知是两个对象。当前通知类型为 `Retraction Notice`，原文为 `Retracted Publication`；通知 `RetractionOf` 指原文，原文 `RetractionIn` 指通知，关联 PMID 可缺失。2025 年前通知旧名 `Retraction of Publication` 仅作历史兼容，不作为唯一当前查询词。[NLM 更名公告](https://www.nlm.nih.gov/pubs/techbull/nd24/nd24_2025mesh_catalog_old.html)、[关系政策](https://www.nlm.nih.gov/bsd/policy/errata.html)

只想识别时可用 `hasretractionin OR retracted publication[pt]` 与 `hasretractionof OR retraction notice[pt]` 分别查原文/通知，不能只排通知就声称剔除了被撤研究。默认检索预览保留二者并标记，不擅自删除；关注声明、勘误、撤稿后重发不得一律当成撤稿。**已实现**仅对原文与通知打布尔标记并保留全部关系；其余关系判断与 Zotero 处置待后续阶段。

交接原始 PMID 集合、检索计划、每步计数和来源报告；每一步过滤记录 `PMID＋决定＋理由＋规则版本＋发生位置`。前端已排除的内容不得在后端统计中再次记成新排除。导入数量、去重数量、全文数量分别报告，不混作“检索成功数”。**当前有界试运行已接通题录与入库后复核**：`lit.metadata_batch` 只接明确1–3 PMID，调用原 PowerShell 引擎；`lit.batch_review` 重新只读查库，输出保留/排除/待核和有效候选清单，不永久删除或合并。失败留回执。真实两篇与同批重跑的独立验收见阶段日志；全量差集自动处理、含附件旧条目实库保护、全文与插件均未完成。

## 6. 已定与待定

已定：官方身份、显式日期、解释留证、异常可见、集合对账、只读预览；规则正文单源，身份表和代码各管自己的事实。

日期口径已按本节产品决定落实。筛选顺序已按本轮 PI 决定落实：前端表达明确范围，入库后 Agent 判断剩余相关性与重复，清理可逆且不永久删除。已有条目的附件、笔记、标签、目录不覆盖；身份或相关性不确定保留待核。撤稿原文与通知分别留出处，从有效候选中剔除。检索、题录导入、复核、全文分别计数和报告，不能将题录成功称为全文完成。

本规范覆盖面大于实测面：七刊身份有官方核实；真实整月采集主要验证 Nature；历史前身、所有主题、所有日期缺失形态、极大单日集合均未证明全面。未来修改须带具体失败、预期行为、反证测试与独立复核，不以增加规则数量为目标。
