## 成功与失败判据

成功须逐项有机器回执或独立结构化判决：GUI和MCP均从输入走到本机全文；同条件共用同一服务、得到相同集合和计数；新Agent能从安装包发现使用；异常计划、断网、无全文、无判断、身份冲突、跨月重复、崩溃恢复及重跑不重复有反例测试；GUI实际渲染与可用操作经观察；文档入口与代码一致；独立复核无未关闭B0/B1。

仅样例成功、模拟代替实机、GUI绕过共用服务、需要用户手工JSON或补点Zotero、将内部函数宣称外部API、仅附件图标/云端存在即称本机全文完成，均不达标。

## 分工与边界

施工：workflow_core（业务服务）、visual_console（GUI/路径）、native_and_plugin（原生适配/MCP/包装）；Orchestrator负责接口裁定、真实试验和终审复算；独立Verifier不继承施工推理，仅契约与候选成品验收。共享仓写域互斥，不撤销他人改动，Git提交由主控统一执行。

真实试验限明确PMID及隔离测试集合，不启动全刊历史大批写入。不碰原两篇42420446/42816625及其附件，不永久删除、不合并旧资料；仅本次精确测试键可移回收站。代码回滚用Git，测试项回滚用回收站。客户端安装包在项目内先完成，受保护客户端配置、账号与外部发布不在授权内；不可用的宿主能力须报告，禁止虚构已安装。

现场兼容修复沿用 `.project/metadata-trial.md` 已登记的原引擎修复授权，以及本轮完整流程授权：原 PowerShell 引擎对显式 CollectionKey 仍强制集合名等于期刊名，阻断已明确选择的隔离集合。仅修此分支为精确编号唯一存在；无编号的刊名唯一匹配、题录身份、去重、JSON 契约与台账不变。修改前留哈希与备份，独立合成复核后落地，再做 dry-run；不重写或复制引擎。

每处失败最多3次，转根因或换法；外部等待有明确超时；预算沿用合同。验收环境为当前Windows、既有公共Python及批准venv、Zotero9.0.6/WebDAV；其他机器/客户端未跑即标未验证。
